Documentation API

L'API REST d'IRM FAIR permet d'accéder à toutes les données de la plateforme depuis vos scripts, notebooks ou outils tiers — projets, animaux, acquisitions, planification, exports BIDS, et plus.

⚡ OpenAPI 3.1 🔐 Session cookie 📊 JSON · CSV · ZIP 🌐 v1.0
Authentification
Connecte-toi via POST /login avec ton compte habituel. Le cookie de session est renvoyé automatiquement par ton navigateur ou ton client HTTP (curl, requests…).
Droits & visibilité
Toutes les routes appliquent les mêmes contrôles que l'interface web : un chercheur ne voit que les projets dont il est membre. Les routes admin retournent 403 sans privilèges.
Format JSON
Les requêtes POST/PATCH attendent Content-Type: application/json. Les exports retournent text/csv ou application/zip selon l'endpoint.

Comment ça marche

3 étapes pour démarrer
1
Authentifie-toi

Envoie un POST /login avec ton identifiant et mot de passe. Le serveur renvoie un cookie de session que tu réutilises sur toutes les requêtes suivantes.

2
Appelle les endpoints

Toutes les routes de données commencent par /api/. Elles renvoient du JSON. Le statut HTTP indique le résultat (200 succès, 403 droits insuffisants, 404 introuvable…).

3
Teste directement ici

Clique sur n'importe quel endpoint plus bas, puis « Try it out » pour le tester en direct — ta session courante est utilisée automatiquement.

Exemples curl

copier-coller dans ton terminal

Connexion (récupère le cookie de session)

# Stocke le cookie dans cookies.txt curl -c cookies.txt -X POST http://localhost:5001/login \ -d "username=admin&password=admin123"

Lister les projets

curl -b cookies.txt GET http://localhost:5001/api/projets

Créer un projet

curl -b cookies.txt -X POST http://localhost:5001/api/projets \ -H "Content-Type: application/json" \ -d '{"nom":"neuro_2026","resp":"Nicolas","nb_animaux_prevus":10}'

Vérifier la disponibilité d'un créneau IRM

curl -b cookies.txt -X POST http://localhost:5001/api/planification/check \ -H "Content-Type: application/json" \ -d '{"date_acq":"2026-06-01","heure_debut":"10:00","duree_min":30}'

Exporter le dataset BIDS d'un projet

curl -b cookies.txt -o bids_tumorigenese.zip \ GET http://localhost:5001/api/export/bids/tumorigenese.zip

Codes de réponse

comprendre les retours HTTP
  • 200 OK — la requête a réussi, le corps contient les données demandées
  • 201 Created — ressource créée avec succès (POST)
  • 400 Bad Request — paramètres manquants ou invalides (vérifie la doc de l'endpoint)
  • 401 Unauthorized — non connecté → fais POST /login
  • 403 Forbidden — connecté mais sans les droits requis
  • 404 Not Found — ressource inexistante
  • 409 Conflict — conflit (par ex. créneau IRM déjà pris, voir response.conflicts)
  • 500 Server Error — bug serveur (signale-le sur Slack)
