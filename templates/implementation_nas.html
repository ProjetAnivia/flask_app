🖥 Implémentation sur NAS Synology
Guide complet pour déployer le Dashboard IRM FAIR sur un NAS Synology DSM 7.1+ · Estimé : ~45 min · Niveau : intermédiaire
Sommaire
① Pré-requis matériel + DSM ② Packages Synology à installer ③ Activer SSH ④ Créer l'arborescence /volume1/IRM_Dashboard ⑤ Transférer le code du projet ⑥ Configurer les variables d'environnement ⑦ Google Calendar (optionnel mais recommandé) ⑧ Lancer le déploiement Docker ⑨ Accéder au Dashboard depuis le réseau ⑩ Importer les vraies données IRM ⑪ Backups et maintenance ⑫ Dépannage
1Pré-requis matériel + DSM
  • NAS Synology compatible Docker (modèles Plus, XS+, FS, SA — voir compatibilité sur synology.com)
  • DSM 7.1 minimum (idéalement 7.2+)
  • RAM : 2 Go libre minimum recommandé pour les conversions DICOM→NIfTI lourdes
  • Espace disque : 50 Go minimum sur le volume1, à augmenter selon le volume de données IRM
  • Compte admin DSM avec droits d'installation de packages et accès SSH
  • Réseau : NAS accessible depuis le VPN universitaire (la machine cliente doit pouvoir ping le NAS)
⚠ Vérifier que la fonctionnalité Docker n'est PAS bloquée par la politique sécurité de DSM (Control Panel → Security → Advanced → désactiver la restriction si nécessaire).
2Installer Container Manager (Docker)
  1. Ouvrir Package Center dans DSM
  2. Rechercher « Container Manager » (anciennement « Docker »)
  3. Cliquer Installer — l'installation prend ~3 min
  4. Une fois installé, lancer Container Manager pour confirmer qu'il démarre bien
✓ Container Manager intègre maintenant docker compose v2 par défaut sur DSM 7.2+. Sur DSM 7.1 il peut s'appeler docker-compose (avec tiret) selon la version installée.
3Activer SSH
  1. Aller dans Control Panel → Terminal & SNMP
  2. Cocher Enable SSH service
  3. Port par défaut : 22 (peut être changé pour la sécurité)
  4. Cliquer Apply

Connexion depuis ton Mac/PC : 

ssh ADMIN_USER@IP_DU_NAS

Remplace ADMIN_USER par ton nom d'utilisateur DSM admin et IP_DU_NAS par l'IP locale du NAS (ex : 192.168.1.42).

4Créer l'arborescence sur le NAS

Le Dashboard sera isolé dans un dossier dédié /volume1/IRM_Dashboard/, séparé de vos vraies données existantes. Vous pourrez transférer progressivement.

Connecté en SSH, exécutez :

sudo mkdir -p /volume1/IRM_Dashboard/{structured,raw,db,logs,secrets,backups}
sudo chown -R $(whoami):users /volume1/IRM_Dashboard
sudo chmod 755 /volume1/IRM_Dashboard
sudo chmod 700 /volume1/IRM_Dashboard/secrets   # secrets non lisibles par les autres
Arborescence créée :
/volume1/IRM_Dashboard/
├── structured/ ← NIfTI + DICOM convertis (convention <projet>/<date_animal>/<seq>/)
├── raw/ ← données brutes constructeur (Bruker, etc.) avant conversion
├── db/ ← base SQLite — NE JAMAIS SUPPRIMER
├── logs/ ← logs applicatifs
├── secrets/ ← google_calendar_sa.json + autres credentials
└── backups/ ← snapshots automatiques de la DB
5Transférer le code du projet

2 options pour copier le code :

Option A — Git (recommandée si repo accessible) :

cd /volume1/IRM_Dashboard
git clone <URL_DU_REPO> app
cd app

Option B — Transfert SCP depuis votre Mac/PC :

# Depuis votre machine locale (PAS le NAS) :
cd /Users/nolan/Documents
scp -r flask_app ADMIN_USER@IP_DU_NAS:/volume1/IRM_Dashboard/app
⚠ Ne PAS transférer le fichier secrets/google_calendar_sa.json via scp dans le dossier app/ — le placer directement dans /volume1/IRM_Dashboard/secrets/. Et vérifier que .gitignore exclut bien ce dossier.
6Configurer les variables d'environnement

Éditer docker-compose.nas.yml et remplacer les valeurs marquées :

cd /volume1/IRM_Dashboard/app
nano docker-compose.nas.yml

1) Générer une SECRET_KEY forte :

python3 -c "import secrets; print(secrets.token_hex(32))"

Copier la sortie dans la ligne SECRET_KEY=…

2) Adresse URL publique :

Remplacer APP_URL=http://IP-DU-NAS:5001 par l'IP réelle, par ex :

APP_URL=http://192.168.1.42:5001

3) SMTP (si vous voulez les emails de reset password) :

Sinon laisser vide, la fonctionnalité sera désactivée.

4) Si vous activez HTTPS via reverse proxy DSM :

HTTPS_ENABLED=true
7Google Calendar (sync agenda mobile)

Si vous voulez que les chercheurs voient les créneaux dans leur app Google Agenda mobile, suivez ces étapes :

  1. Sur console.cloud.google.com, créer un projet "IRM-Dashboard"
  2. Activer l'API Google Calendar
  3. Créer un Service Account → télécharger la clé JSON
  4. Sur calendar.google.com, créer un calendrier "IRM Dashboard"
  5. Partager le calendrier avec :
    • L'email du service account avec droit "Apporter des modifications"
    • Les 3 chercheurs avec droit "Apporter des modifications aux événements"
  6. Copier le JSON sur le NAS : 
    scp irm-dashboard-XXXXX.json ADMIN_USER@IP_DU_NAS:/volume1/IRM_Dashboard/secrets/google_calendar_sa.json
ssh ADMIN_USER@IP_DU_NAS "chmod 600 /volume1/IRM_Dashboard/secrets/google_calendar_sa.json"
  7. Dans docker-compose.nas.yml, remplir GOOGLE_CALENDAR_ID=<ID-DU-CALENDRIER>@group.calendar.google.com
8Lancer le déploiement Docker
cd /volume1/IRM_Dashboard/app
sudo docker compose -f docker-compose.nas.yml up -d --build

Le premier build prend ~5-10 min (téléchargement de l'image Python et installation des dépendances).

Vérifier le démarrage :

sudo docker compose -f docker-compose.nas.yml logs --tail 30 irm-app

Vous devriez voir :

[scheduler] démarré
[gcal-pull] démarré (poll 120s)
[INFO] Listening at: http://0.0.0.0:5000
✓ Le Dashboard est lancé. Statut du container : sudo docker ps | grep irm_fair_app
9Accéder au Dashboard depuis le réseau

Ouvrir un navigateur :

http://IP_DU_NAS:5001

Identifiants par défaut :

  • admin / admin123 → CHANGER LE MOT DE PASSE IMMÉDIATEMENT
  • operateur / op123
  • chercheur / ch123

Accès depuis l'extérieur (VPN universitaire) :

  1. S'assurer que le port 5001 est ouvert dans le firewall DSM
  2. Vérifier que le NAS est accessible depuis le VPN (ping IP_DU_NAS)
  3. Idéalement : configurer un reverse proxy DSM avec HTTPS (Control Panel → Login Portal → Advanced → Reverse Proxy)
10Importer les vraies données IRM

Phase 1 — Tests : commencez par 1 ou 2 acquisitions de test via l'interface Import du Dashboard. Vérifier que tout fonctionne (NIfTI affiché, métadonnées correctes, créneau Google Agenda visible).

Phase 2 — Migration en masse :

  1. Identifier le dossier des vraies données (ex : /volume1/Recherche/IRM/)
  2. Choisir si migration par copie ou par lien symbolique : 
    # Copie complète (sécurisé, mais double l'espace)
sudo cp -r /volume1/Recherche/IRM/* /volume1/IRM_Dashboard/structured/

# Lien symbolique (instantané, mais lie les 2 emplacements)
sudo ln -s /volume1/Recherche/IRM /volume1/IRM_Dashboard/structured/legacy
  3. Lancer la réparation automatique des noms depuis le Dashboard (admin) : 
    curl -X POST http://IP_DU_NAS:5001/api/nas/fix-naming \
     -H "Cookie: session=<votre-cookie-admin>"
    Cette commande renomme tous les fichiers pour respecter la convention <projet>/<AAAAMMJJ_AnimalID>/<sequence>/.
⚠ Faire un snapshot DSM avant la migration en masse (Storage Manager → Snapshot).
11Backups & maintenance

Backup automatique de la DB (Hyper Backup ou cron) :

# Cron job (1 fois par jour à 3h du matin)
0 3 * * * cp /volume1/IRM_Dashboard/db/irm_fair.db \
              /volume1/IRM_Dashboard/backups/irm_fair_$(date +\%Y\%m\%d).db

Mises à jour du code :

cd /volume1/IRM_Dashboard/app
git pull   # ou re-scp depuis votre machine
sudo docker compose -f docker-compose.nas.yml up -d --build

Logs en temps réel :

sudo docker compose -f docker-compose.nas.yml logs -f irm-app

Stop / Restart :

sudo docker compose -f docker-compose.nas.yml restart irm-app
sudo docker compose -f docker-compose.nas.yml stop irm-app
12Dépannage
SymptômeSolution
Container ne démarre pas Voir docker compose logs irm-app. Erreur classique : permissions sur /volume1/IRM_Dashboard/db. Faire sudo chmod -R 755 /volume1/IRM_Dashboard/db.
Port 5001 déjà utilisé Changer le port dans docker-compose.nas.yml (ex : "5002:5000") et mettre à jour APP_URL.
Google Agenda iframe blanche Le calendrier doit être partagé publiquement ou les utilisateurs doivent être connectés à un compte Google qui y a accès. Voir page Planning.
SECRET_KEY warning au démarrage La SECRET_KEY est restée à la valeur par défaut. Générer une nouvelle clé et l'écrire dans le compose.
Fichiers NIfTI non trouvés Vérifier le mount du volume : docker exec irm_fair_app ls /nas/structured. Si vide, le mount échoue → vérifier /volume1/IRM_Dashboard/structured.
DB corrompue Restaurer depuis le dernier backup dans /volume1/IRM_Dashboard/backups/, copier vers db/irm_fair.db, restart.
